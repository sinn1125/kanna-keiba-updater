# Ver.6 A方式：追い切り欠損・更新状態対応設計

状態: 設計仕様（未実装・未検証）。既存の自動更新処理・予測結果を変更しない。

## 原則
- 追い切り未取得でも予測を継続する。欠損を「調教なし」「評価0点」と解釈しない。
- 取得できた馬だけを不当に有利にしない。欠損パターン別に学習・校正・検証したモデルを使用する。
- 取得不能な情報を実測値として創作しない。過去データを代用する場合は「過去の値」と表示し、現況確認済みと区別する。
- 予測継続と馬券推奨は別判定。最新出走馬・取消・オッズの確認が不十分なら馬券推奨を保留する。
- 手動印、既存予想、過去戦績、地方データ、端末内記録を破壊しない。中央競馬のみを対象とする。

## データ状態
各レース・馬・項目に source, event_time, fetched_at, checked_at, updated_at, completeness, status, error_code, version を保持する。
status は confirmed / partial / not_published / not_entered / fetch_failed / stale / invalid / not_applicable を区別。
「未発表」「未入力」「通信失敗」「古い」「適用外」を同じ null に潰さない。
最終成功データは保持し、失敗時に新規の正常値として上書きしない。表示には取得日時と状態を添える。
タイムゾーンは JST で表示、保存時刻はオフセット付きの時刻とする。

## 追い切り欠損の予測
- full: 当該レースで必要な追い切りの対象期間・種類・馬ごとの充足状況を満たす。
- partial: 一部の馬・期間・調教種類のみ取得。
- absent: 全馬未取得。
- full/partial/absent を独立に時系列検証し、校正済みの共通ベースライン（追い切りなし）を常備する。
- partial では取得有無そのものによるバイアスを検証し、追い切り特徴量を用いる場合は欠損指標・取得経路を考慮する。
- 特徴量欠損をゼロと置かない。補完値を用いる場合は補完フラグを付け、学習時にも同じ処理を再現する。
- 追い切りデータを使うモデルが未使用期間の検証で改善しなければ、共通ベースラインを優先する。
- レース内で勝率合計100%、各馬で P(1着) <= P(2着以内) <= P(3着以内) を満たす。
- モデル切替に伴う確率の変化と不確実性を記録する。

## 更新・予測・馬券推奨のゲート
- 重要度A: 出走馬、取消、馬番、レース同定、発走時刻、券種別オッズ。整合性・鮮度を満たさなければ新しい馬券推奨を保留。
- 重要度B: 過去戦績、馬場、騎手変更、斤量等。欠損時は暫定予測、条件に応じ不確実性増加。
- 重要度C: 追い切り、補助指標。欠損対応モデルへ切替、欠損を表示。
- 重要度は固定的に扱わず、対象レースと時点に応じて検証済みの閾値を定める。
- オッズなしでも能力予想は表示。期待値や回収率を算出せず「計算保留」とする。
- 出走取消・騎手変更が未確認の可能性がある場合、古い予想は参考として表示し、推奨買い目の新規生成を停止する。
- 取消等で出走馬が変化したら、過去の予想を消去せず無効化・再計算する。
- 更新が失敗しても最後の正常スナップショットを保持し、未確認状態を明示する。

## UI
- レース単位: データ取得状態、最終確認時刻、予測信頼性、買い目推奨可否を別々に表示。
- 馬単位: 追い切りの「取得済み/一部/未取得/未入力」、対象期間、取得元、時計の件数。
- 予測の根拠: 「追い切り未取得のため戦績・適性・展開で評価」と明記。
- 取得率だけで信頼性を決めず、重要項目の鮮度とモデルの予測不確実性を別表示。

## テスト・受入条件
1. 全馬追い切りなし、一部のみ、全馬ありの3パターンで予測が継続する。
2. 未取得を0点扱いしない。取得済み馬だけが機械的に有利にならないことを比較検証する。
3. 通信失敗時に既存の正常データを保持し、更新成功と誤表示しない。
4. オッズ未取得、出走取消未確認時に期待値・買い目推奨を保留する。
5. 発走時点以降の情報を過去の予測に混入させない。
6. 確率整合性、同一入力での再現性、変更前モデルとの時系列比較を確認する。
7. 手動入力の追い切り・印・端末内記録を更新処理で消去しない。

## 実装順
(1) 状態スキーマとデータ保持のテスト → (2) 欠損対応ベースライン → (3) partial/fullモデル比較 → (4) 推奨ゲート → (5) UI → (6) 時系列検証。
