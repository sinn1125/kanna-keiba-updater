# kanna-keiba-updater

JRA公式データの更新専用リポジトリ。競馬ブックSmart・地方競馬は自動取得しません。

## 継続更新と障害復旧

- 日本時間9:00、9:07〜16:37の毎時07・37分、17:07に起動を予約。結果・オッズは起動後最大30分間、同じrunnerで繰り返し確認します。毎日の公式開催リンクで開催を判定するため、月曜・祝日開催にも対応します。GitHubの予約実行は遅延・欠落する場合があり、厳密な10分間隔の保証ではありません。
- アプリやWorkを閉じていてもGitHub Actionsで動作します。手動実行はActionsの `Official racing data update` → `Run workflow` から可能です。
- 出馬表・過去戦績・AI予想・確定結果・オッズを独立したトランザクションで処理します。失敗した処理は書き込みを元に戻して最大2回試行し、他の処理を継続します。
- 検査済みの更新は一部失敗時も保存します。失敗したデータは以前の値を維持し、次の予約実行で再試行します。取得できない情報を新しい実測値として補完しません。
- 一部失敗でも `update-report.json` とfeedの `results[].stages` に失敗を記録し、Actionの最終結果は失敗にします。`success:true, partial:true` は「配信データの保全検査は合格、一部の取得処理は失敗」を表し、全取得成功を意味しません。
- 各取得は既存の処理予算内で実行。定期実行の結果・オッズは最大30分の継続セッション、ジョブ上限40分です。同じ項目だけをconcurrencyで直列化し、他の項目を一緒に待たせません。
- 開催一覧が通信エラーになった場合は、保存済みの当日公式出馬表があれば当日の取得を継続します。当日の根拠がなければ開催を推測せず失敗を報告します。
- 過去日・安定ID・保存済み印/メモ/戦績を保全検査します。出走馬が一致しない保存済み予想は削除せず、現在の配信対象から外します。モデルの自動採用・再学習は行いません。
- 更新診断はActionのSummaryと7日間保存するArtifactに残します。GitHub側でワークフローが無効化された場合やサービス停止時は、自動復旧を保証できません。失敗通知はGitHubの通知設定に従います。

## 検証

`python -m unittest discover -s tests`

一時通信エラー、途中書き込み、予想処理の例外、件数不一致、不正オッズ、時間切れ、全取得失敗を注入し、再試行・ロールバック・正常な更新の保存を検証します。


## 項目ごとの独立実行（2026-10-18）

現在の予約更新は、同じ時刻を起点に次の6ジョブを別々に実行・検査・保存します。

| ジョブ | 保存対象 |
| --- | --- |
| entries | 出馬表、枠順、馬番、騎手、斤量、取消 |
| weights | 馬体重・増減のみ |
| histories | 未取得の過去戦績 |
| forecasts | 未生成レースの既存モデルによるAI予想 |
| results | 公式の確定結果・払戻・ラップ等 |
| odds | 公式に掲載された各券種のオッズと単勝表示 |

- 一つの失敗で他のジョブを中止しません（`fail-fast: false`）。各ジョブが個別の診断Artifact・結果を残します。
- 最大4ジョブ、各HTTP取得ワーカー1本で、接続を増やし過ぎないようにします。実行枠を待つジョブがあります。
- 保存時に最新のmainを読み直し、変わった項目だけを3方向比較で統合します。別ジョブの変更・手動記録・過去日を保持します。同じ項目が競合した場合は上書きせず、当該ジョブだけを失敗にして次回に再試行します。
- 検査済み配信データ `dist/feed.json` は、各ジョブの保存時に最新データから構成します。ジョブ別の状態は `dist/update-status/<component>.json` とfeedの `results[0].stages` に記録します。
- 手動実行では `component` から単独ジョブも選べます。`all` は全項目です。
- 馬体重と出馬表は同じ公式ページを参照しますが、保存する項目を分けます。出馬表の馬場情報（baba）も保存し、発走前の予想は更新のたびに再計算します。
- 結果・オッズは取得開始から120秒以上空けて次回確認します。1回の処理が長い場合は完了を待ちます。17:15以降は次の取得を開始しません。手動実行・コード変更時は従来の単発取得です。GitHub側の起動遅延や公式公開待ちは残ります。


### 馬場状態補正
良・稍重・重・不良を芝とダート別に読み取ります。同じ馬場とそれ以外の馬場の過去成績を比較し、各2走以上ある場合だけ、実績数に応じて小さく補正します。過去データは予想日より前の同じ走路種別に限定。未取得・実績不足・障害は補正ゼロ。根拠は `evidence.trackCondition` に保存。既存学習済みモデルの係数を変更せず、最大±0.25の対数オッズ補正を行う暫定ルールです。精度改善・確率の校正は未検証です。発走後の保存済み予想は上書きしません。


### 現行構成での更新改善
外部サーバー・他社AI・TARGETへの接続は使用しません。予約起動後の結果・オッズを同じGitHub runner内で繰り返し取得し、毎回検査・保存します。各回は最新mainの生成済みスナップショットだけを読み直し、ソースや手動メモの作業ツリーはリセットしません。結果・オッズを実行順の先頭に置きます。実際の間隔は処理時間・通信・GitHubの起動待ちに左右され、2分ごとの保証ではありません。外部用run-live-worker.pyは未稼働の準備コードとして残っています。
